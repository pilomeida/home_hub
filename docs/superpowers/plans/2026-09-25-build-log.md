- Status: DONE

Investigation (resolved by coordinator ruling): `validate_classification`, as
specified, raises `errors["file"] = "Choose a file to upload"` for any
DOCUMENT-kind category with no file. That pre-empted two downstream checks
the plan also specifies (`create_record`'s "category is filed from a
document, not entered by hand" and `refile_record`'s "can only become a
document if it has a file attached"), so their two Step-1 tests
(`test_record_categories_reject_document_only_use_and_vice_versa`,
`test_refile_record_to_a_document_category_needs_its_file`) failed as
written against the plan's own reference implementation. I stopped and
logged this as BLOCKED rather than pick a fix. Coordinator ruling: keep the
tests and `validate_classification` unchanged (it's correct for the
upload/Inbox path); instead `create_record` and `refile_record` now check
the target category's kind via a new private `_target_kind(classification)`
helper *before* calling `validate_classification`, raising their own
specific error first. `create_record` keeps its post-validation check too,
as a safety net. Full suite green: 403 passed, 0 failed.

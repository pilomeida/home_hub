# Financial OS — Data Model Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Account, Commitment, Debt, and Person tables plus four new nullable columns on `Transaction` (`account_id`, `commitment_id`, `debt_id`, `nature`) that every later Financial OS sub-project depends on.

**Architecture:** One new SQLModel file per entity (`app/models/account.py`, `person.py`, `commitment.py`, `debt.py`), following the existing one-file-per-entity pattern (`document.py`, `transaction.py`, `utility_reading.py`). `Nature` is a new enum added to the existing `transaction.py`, since it's a `Transaction`-owned field, matching how `Category`/`TransactionType` already live there. Each task pairs a model change with its own Alembic migration, generated via `alembic revision --autogenerate` and verified against a scratch copy of the real database — never against `data/home_family.db` directly.

**Tech Stack:** SQLModel, Alembic (SQLite, `render_as_batch=True` already configured in `alembic/env.py`), pytest.

**Spec:** `docs/superpowers/specs/2026-08-21-data-model-foundation-design.md`

## Global Constraints

- Additive only: no column removals, no altering of existing `Category`/`TransactionType` enum values, no changes to any existing table's existing columns.
- No backfill: all four new `Transaction` columns are nullable and every existing row (3,726 of them) must remain valid with them unset.
- Every new model file gets a matching entry in `app/models/__init__.py` (metadata registration depends on it — the test `engine` fixture imports `app.models` and calls `SQLModel.metadata.create_all`).
- Every migration must be verified with both `upgrade head` and `downgrade -1` against a scratch copy of `data/home_family.db`, never the real file.
- Commands run directly with `pytest` / `python3 -m alembic ...` — no venv activation needed locally (dependencies are already importable from system Python in this environment).

```python
from typing import Optional
```

```python
"""Debt: formal (mortgage-style) or informal (person-to-person) debt,
one shape for both, distinguished by whether a payment schedule exists.
Formal debt links to a Commitment for its recurring payment; informal
debt links directly from Transaction.debt_id instead, since ad-hoc
loans have no fixed schedule to attach a Commitment to."""

from datetime import datetime
from enum import Enum
from typing import Optional

from sqlmodel import Field, SQLModel


class DebtKind(str, Enum):
    FORMAL = "formal"
    INFORMAL = "informal"


class DebtDirection(str, Enum):
    OWED_TO_US = "owed_to_us"
    OWED_BY_US = "owed_by_us"


class Debt(SQLModel, table=True):
    __tablename__ = "debts"

    id: Optional[int] = Field(default=None, primary_key=True)
    kind: DebtKind
    person_id: Optional[int] = Field(default=None, foreign_key="people.id")
    direction: Optional[DebtDirection] = None
    original_amount: float
    current_balance: float
    interest_rate: Optional[float] = None
    commitment_id: Optional[int] = Field(default=None, foreign_key="commitments.id")
    created_at: datetime = Field(default_factory=datetime.utcnow)
```
